# Intel News Feed 📰

Automated Threat Intelligence platform that aggregates, enriches, filters, and reports on the latest cybersecurity news from trusted industry sources — with a live dashboard and optional email alerting for high-severity findings.

## 🚀 Overview

This project runs an automated pipeline to monitor and track the cybersecurity landscape:

1. **Ingests** data from five security news sources: The Hacker News, BleepingComputer, Krebs on Security, Dark Reading, and CISA Advisories.
2. **Enriches** every article with a severity score, extracted CVE IDs, and best-effort IOCs (IPs/hashes) — see [Data enrichment](#-data-enrichment).
3. **Persists** the full history in `data/feed_database.json`, committed to the repo so it accumulates real trend data over time (it's no longer rebuilt from scratch on every run).
4. **Filters** news based on a curated list of high-priority security keywords (e.g., "0day", "ransomware", "critical") and excludes noise via a blacklist.
5. **Generates** clean Markdown reports in `reports/`, an aggregated `data/summary.json`, and a live [dashboard](#-dashboard).
6. **Alerts** by email when a Critical/High severity finding shows up in the daily report (optional, see [Email alerts](#-email-alerts)).

## 🛠️ Technology Stack

- **Language:** PowerShell (Core)
- **Automation:** GitHub Actions (ingestion cron, dashboard deploy, test suite)
- **Intelligence Sources:** The Hacker News, BleepingComputer, Krebs on Security, Dark Reading, CISA Advisories
- **Dashboard:** static HTML/CSS/vanilla JS (no framework, no build step), published via GitHub Pages
- **Testing:** Pester
- **Output:** Markdown (`.md`) reports + JSON (`data/feed_database.json`, `data/summary.json`)

## 📖 Usage & Functions

Dot-source `IntelNewsFeed.ps1` to load every module, then call any of the reporting functions directly:

### Daily Report
Checks for news published on a specific date (defaults to yesterday if no date is provided). Also sends the Critical/High alert email, if configured.
```powershell
Get-NewsByDate -TargetDate "2026-07-15"
```
### Monthly Summary
Aggregates all relevant security news published during a specific month.
```powershell
Get-NewsByMonth -TargetMonth "2026-06"
```
### Custom Range
Generates a report for a specific window of time.
```powershell
Get-NewsByRange -StartDate "2026-07-01" -EndDate "2026-07-15"
```

Running `IntelNewsFeed.ps1` directly (no parameters) does the daily default: `Get-NewsByDate`, `Get-NewsByMonth`, then refreshes `data/summary.json` for the dashboard.

## 🧪 Data enrichment

Every article gets three enrichment passes (`modules/Enrichment.ps1`) before it's saved to `data/feed_database.json`:

- **Severity** (`Critical` / `High` / `Medium` / `Low`) — uses an explicit CVSS score mentioned in the article text when present (≥9 Critical, ≥7 High, ≥4 Medium), otherwise falls back to keyword heuristics (e.g. "0day", "actively exploited" force at least High).
- **CVEs** — every `CVE-YYYY-NNNNN` mentioned in the title or introduction, deduplicated.
- **IOCs** — best-effort extraction of IPv4 addresses and file hashes (MD5/SHA1/SHA256). News summaries are journalistic text, not technical bulletins, so this is often empty — that's expected, not a bug.

## 📊 Dashboard

A live dashboard is published via GitHub Pages at:

**https://davimarinho01.github.io/intel-news-feed-dashboard/**

*(Requires GitHub Pages to be enabled once — see [Setup](#-setup) below.)*

It reads `data/summary.json` (generated by `modules/Dashboard.ps1` on every pipeline run) and renders, entirely client-side:

- KPI row (total articles, critical/high counts, sources tracked)
- Severity distribution (status-colored bars)
- Articles per source
- Daily trend by source (interactive line chart with hover tooltip + table-view toggle)
- Top mentioned CVEs (colored by severity, linked to the source article)
- Top keywords
- A table of the most recent Critical/High findings

Supports light/dark mode (follows system preference, with a manual toggle that persists). No build step — `dashboard/index.html`, `styles.css`, and `app.js` are plain files; `.github/workflows/pages-deploy.yml` copies the latest `data/summary.json` into place and publishes on every push that touches it.

## 📧 Email alerts

`modules/Notify.ps1` sends an email whenever the daily report contains a Critical or High severity finding. It's entirely optional: if unconfigured, `Get-NewsByDate` just skips it silently.

To enable it, add these **repository secrets** (Settings → Secrets and variables → Actions):

| Secret | Example | Notes |
|---|---|---|
| `SMTP_SERVER` | `smtp.gmail.com` | |
| `SMTP_PORT` | `587` | Optional, defaults to `587` |
| `SMTP_USER` | `alerts@example.com` | Also used as the `From` address |
| `SMTP_PASS` | *(app password)* | Use an app password, not your real account password |
| `ALERT_EMAIL_TO` | `security-team@example.com` | Recipient |

## 📋 Report Structure

Each generated report includes an Executive Summary and detailed findings per article:

- Metric Table: total count of news, source breakdown, severity breakdown.
- Top Mentions: most frequent threat indicators identified.
- Article Details: title, source, severity, CVEs (when any), UTC publication timestamp, brief introduction, and a direct URL.

## 🧰 Testing

Pester tests cover the pure enrichment/filtering functions (no network required):

```powershell
Install-Module -Name Pester -MinimumVersion 5.5.0 -Scope CurrentUser
Import-Module Pester -MinimumVersion 5.5.0
Invoke-Pester -Path tests
```

`.github/workflows/tests.yml` runs the same suite on every push and pull request.

## 🤖 Automation Schedule

Three GitHub Actions workflows drive the project:

| Workflow | Trigger | Does |
|---|---|---|
| `news-check.yml` | Daily at `03:00 AM UTC` (+ manual) | Runs the pipeline, commits `reports/*.md` and `data/*.json`, sends alert email if configured |
| `pages-deploy.yml` | Push touching `data/summary.json` or `dashboard/**` (+ manual) | Publishes the dashboard to GitHub Pages |
| `tests.yml` | Push to `main` + pull requests | Runs the Pester suite |

## ⚙️ Setup

1. Clone the repo and enable GitHub Pages once: **Settings → Pages → Source: "GitHub Actions"**.
2. (Optional) Add the SMTP secrets above if you want email alerts.
3. The daily workflow needs no further setup — it runs on the schedule already committed in `news-check.yml`.
